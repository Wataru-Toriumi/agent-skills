# 要求から実装・検証・PRへ

[implement-work-item](../plugins/forge/skills/implement-work-item/SKILL.md) を選ぶと、
一件の作業項目について実装・検証・提出の進行状態を記録する。
既存スキルは単独でも使え、この手順や他のプラグインの導入を必須にしない。

## 工程間で渡す情報

| 項目 | 内容 |
| --- | --- |
| 入力 | 作業ID、要求ID、設計資料、リポジトリ、開始SHA |
| 範囲 | 変更可能箇所、許可操作、対象外、依頼の到達点 |
| 合格条件 | 受け入れ条件、検証コマンド、必要なレビュー |
| 状態 | 未着手・実行中・判断待ち・検証失敗・完了 |
| 証跡 | 対象SHA、未コミットなら差分の識別情報、実行結果・ログ、レビュー結果 |
| 再開条件 | 未解決事項、次の工程、再試行回数・上限、判断事項と担当 |

要求と条件をinkから受け取り、必要に応じてprobeで検証方法を整理する。
forgeで実装・検証・レビューし、依頼に応じてコミット・PRへ進む。
記録の書式は [作業記録のひな形](../plugins/forge/skills/implement-work-item/assets/work-record.md) を参照する。
保存先の指定がなければ会話内で扱う。

## 完了と再開の例

「申請者以外が申請内容を閲覧できないこと」が受け入れ条件なら、正常な閲覧と権限拒否を検証し、
対象SHA・結果・レビューを記録する。PR作成だけでは完了にならない。
CIが失敗した場合は検証失敗として次の修正へ引き継ぐ。

再開時にheadが変わっていたら、記録との差分を確認する。権限判定を修正したなら、
そのテストとレビューを更新する。検証した内容を変更せずコミットした場合は、内容一致を確認して証跡を新しいSHAに対応づける。
判断や権限が足りなければ判断待ちにし、無関係な工程まで繰り返さない。
