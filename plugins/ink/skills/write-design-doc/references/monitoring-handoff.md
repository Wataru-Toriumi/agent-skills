# 設計変更を pulse の監視設計へ渡す

利用経路、非同期処理の完了、失敗時の影響、依存先、信頼性目標などが変わり、既存の監視や初動がそのまま使えない場合に、利用可能な pulse の `plan-monitoring` を使う。
文言や内部構造の変更だけで観測する挙動が変わらなければ、監視の再設計を一律に行わない。

1. 要求 ID・設計の版、変更前後の経路、成功・失敗・遅延の判定、利用者への影響を渡す。提案中の設計と稼働中の構成を区別する。
2. 既存の指標・ログ・通知条件と初動、合意した SLI・SLO、対象環境・対応時間帯・担当を渡す。未計測の指標や未合意の閾値は未定とし、存在する設定として扱わない。
3. 段階移行なら新旧の共存期間、経路ごとの観測方法、旧監視を外せる条件を示す。切り戻しの前提や復旧条件も、設計で確認できる範囲を渡す。
4. 指標・判定条件・通知先・初動・検証方法、計測不足と未決事項を受け取り、設計の検証・運用条件へ反映する。必要な計測や運用作業を実装項目に含める場合も、今回の依頼範囲と採否を保つ。

設計したことと、設定の作成・適用・通知検証が済んだことを分ける。計画だけの依頼で本番設定や通知先を変更しない。
設計レビューから使う場合は、戻った案を評価材料として返す。レビューだけの依頼で設計文書を書き換えない。
pulse が未導入でも、検知したい失敗・既存監視への影響・不足する計測・確認方法を整理して進める。
