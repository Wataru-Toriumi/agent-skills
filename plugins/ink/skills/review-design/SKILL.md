# 設計の頑健性をレビューする

要求を満たす条件と、設計が破綻する条件を具体化し、実装・採用の判断に必要な指摘を返す。
ATAM の考え方で重要なリスクを選び、ARID を参考に設計を具体的に使って確かめる。
競合や状態遷移が複雑な箇所は、必要に応じてモデルを実行する。

## 対象と判断基準を揃える

- 指定された設計と関連する要求・ADR・コードを読み、今回の変更範囲と現状を区別する。Design Doc や PRD が揃っていなくても、与えられた設計から進める。
- 主要要求、アクターごとの権限、受け入れ条件、確定した制約、対象外を拾う。既存の要求 ID を引き継ぎ、何を満たせば成立する設計か示す。
- 「再送しても注文は一つ」「権限のない利用者は他者のデータを読めない」など、処理の途中や失敗時にも守るべき条件を特定する。入力にない条件は仮定として扱い、合意済みの要求にしない。
- コードは現状の根拠として読む。提案された変更がまだ実装されていないことを欠陥として扱わない。判断を左右する情報が不足していれば、その影響を示し、確認可能な範囲の評価を続ける。

## シナリオで設計を追う

1. **選ぶ:** 主要な正常系と、要求への影響が大きい失敗・変更のシナリオを選ぶ。同時実行、重複・順序逆転、依存先の停止、負荷増加、権限変更、移行や切り戻しなどから、今回の構成と要求に関係するものだけを使う。
2. **具体化する:** 状況、起点となる操作や出来事、対象、期待する応答、合格条件を置く。未定の負荷や応答時間を一般的な数値で埋めず、未決の基準と確認方法を示す。
3. **使って追跡する:** 呼び出し側の立場で、提案された API やモジュールを使う短いコード・擬似コードを組み立てる。入力・返り値・エラー・状態変化を追い、要求を実現できるか確かめる。構成や移行の設計なら操作列で同様に追う。境界で失敗・再送・競合したとき、守るべき条件が崩れないか確認し、不足する操作や契約を都合よく補わない。
4. **評価する:** 要求違反につながる経路と根拠を示す。結果を左右する前提や設定、それを変えた場合の影響も確認する。対策で増える遅延・複雑さ・運用負担などを含め、要求に見合う最小限の改善を提案する。
5. **確かめる:** 机上で判断できる点と、実行が必要な点を分ける。実行順序の組み合わせが判断を左右する場合は、対象を絞った状態モデルを作り、利用可能な Quint や TLA+ / TLC などで探索する。実装・試作品があれば既存テストやモデルベーステストも選べる。実行方法を決める際は [モデル実行の進め方](references/model-execution.md) を参照し、実行できなければ理由と必要な検証を残す。

観点の選択やトレードオフの整理に迷う場合は [フレームワークの使い方](references/framework.md)、指摘の粒度は [レビュー例](references/review-example.md) を参照する。

## 指摘と不確実性を分ける

- **設計上の問題:** 要求に違反する条件と経路を、設計の節・図・コードを根拠に説明できるもの。
- **説明不足・未決事項:** 設計の記載から挙動や前提を判断できないもの。「記載がない」だけで機構自体が存在しないと断定せず、必要な確認を示す。
- **検証未実施:** 設計に方針はあるが、成立の判断に計測・試験などが必要なもの。既知の欠陥や検証成功と混同しない。

合意済みのトレードオフは、新しい要求違反や前提の変化がなければ欠陥として再指摘しない。
単なる好み、対象外の改善、同じ原因の重複を省く。指摘数を埋めず、問題が見つからなければ確認した範囲と限界を示す。

## 結果を返す

- **重要な指摘:** 影響の大きい順に、見出し、優先度、対象、発生条件と影響、根拠、改善案、検証方法を示す。優先度の基準がなければ、「採用・実装前に解消」「実装時に対応」などの対応時期と理由を示す。
- **未確認事項:** 説明不足・未決事項と検証未実施を区別し、判断への影響と確認方法を示す。指摘がなくても、重大な未確認事項は明示する。
- **確認範囲と残るリスク:** 対象資料と主要シナリオ、検証方法（机上での追跡・シミュレーション実行・モデル検査・実装のテスト）と実際の結果を要約する。実行した場合は再現方法と探索範囲・未完了の有無を残す。未確認の経路や採用する場合に受け入れるリスクを明示し、無条件の安全宣言や根拠のない点数を付けない。

既定の出力先は会話。指定された書式や保存先があれば従い、空の節や長いチェックリストは作らない。
必要な検証用モデルや試験コードは一時的な隔離場所で扱う。レビューだけの依頼では、製品の設計・コードの修正、恒久的な成果物の追加、外部へのコメント投稿まで進めない。
