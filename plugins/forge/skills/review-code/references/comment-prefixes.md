# コメントの接頭辞

PR コメントの先頭に、伝えたい意図に合う接頭辞を一つ付ける。`[nits] 本文` のように角括弧で囲み、半角スペースを空けて本文を書く。これは forge の既定とし、利用先の規約があれば優先する。

| 接頭辞 | 用途 | 例 |
| --- | --- | --- |
| `[nits]` | 動作に影響しない軽微な改善。対応は任意で、マージを妨げない | `[nits] 説明文の「申請済み」を画面と同じ「提出済み」に揃えると読みやすそうです。` |
| `[imo]` | 複数の妥当な選択肢がある中での意見・提案。理由やトレードオフを添える | `[imo] この判定を共通化すると、2か所の条件を同時に修正する負担を減らせそうです。` |
| `[question]` | 仕様や意図など、判断に必要な確認 | `[question] 承認後の取消は今回の対象に含まれますか？` |
| `[issue]` | 条件と根拠を確認できた不具合や回帰 | `[issue] [P1] 再送時にも決済を実行するため、二重請求が発生します。` |

`imo` は「in my opinion」を意味し、重要度や対応の必須・任意を表さない。
提案が任意ならその旨を、マージ前の判断が必要なら理由を本文に添える。
接頭辞は P0〜P3 の重要度と分け、必要な修正を柔らかく見せるために `[nits]` や `[imo]` を使わない。
根拠不足の懸念は `[question]` にし、不具合として断定しない。

ラベルを使うために好みだけの指摘を増やさない。変更内容や検証結果を伝えるだけの返信には接頭辞を付けず、返信の中で新たな提案や質問をする場合に使う。
受け取った接頭辞は意図の手掛かりとして扱う。`[nits]` でも本文が重大な問題を示していれば根拠を確認し、`[imo]` を一律に任意扱いしない。
