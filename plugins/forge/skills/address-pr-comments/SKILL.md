# PR コメントに対応する

コメントの意図と現行コードを照合し、対応内容と残る判断を追える状態にする。
確認だけ、修正まで、PR への反映、返信までなど、今回の依頼と既に合意した操作範囲に合わせる。
確認や返信案だけの依頼ではコードや GitHub の状態を変更しない。GitHub への返信やスレッドの解決は依頼に含まれる場合に行う。

## 対象と会話を確認する

- リポジトリの指示、対象 PR、base/head、最新 head の SHA、作業ツリーを確認する。PR の URL や番号がなければ現在のブランチとの対応を調べ、候補が複数なら対象を確認する。
- 既存 PR の修正はその head ブランチで進める。未コミットの変更を保持し、別作業と混ざる場合は作業場所を分ける。手元が古い場合は差分を確認して取り込み、履歴を勝手に書き換えない。
- 指定された範囲の一般コメント、レビュー本文、行・ファイルへのコメントと返信を読む。ページ分割を含め、未取得の範囲を残したまま「すべて確認済み」としない。取得できなければ確認できた範囲を示す。
- コメント URL・ID、スレッド、対象ファイル、指摘時点のコード、解決済み・古い差分かを対応付ける。古い差分へのコメントも現行コードで問題が残るか確認する。取得と返信先の区別は [コメントの扱いと対応例](references/comment-handling.md) を参照する。

## 対応方針を決める

各コメントを次の観点で整理する。同じ原因の指摘はまとめて扱い、元のコメントとの対応を残す。

| 方針 | 判断と対応 |
| --- | --- |
| 修正する | 発生条件と影響を確かめ、依頼範囲で必要な修正を行う |
| 説明する | 質問や誤解に対し、仕様・コード・検証結果を根拠に答える |
| 確認する | 再現条件、期待動作、相反する指摘など、判断に必要な点を絞る |
| 今回は変更しない | 指摘が成立しない、または PR の範囲外である理由と影響を示す |
| 対応済み | 現行コードと検証結果から解消を確認し、該当する変更を示す |

- 提案や suggestion をそのまま適用せず、現行コード・仕様・呼び出し元に照らして判断する。レビュー者や bot の断定だけを根拠にしない。
- `[nits]`・`[imo]` などは意図の手掛かりとして読み、本文の根拠や対応の必要性を確かめる。扱いは [コメントの接頭辞](../review-code/references/comment-prefixes.md) に従う。
- 必要に応じて [review-code](../review-code/SKILL.md) の観点で調べ、不具合・質問・改善提案を区別する。「再現しなかった」と「起こらない」を同一視しない。
- 両立しない指摘や仕様を変える判断は、争点と選択肢を示す。判断待ちの箇所を保留し、独立して対応できるものは進める。範囲外の課題は切り出し案を示し、Issue の作成は依頼に応じて行う。

## 修正して検証する

1. 原因に対する修正と必要なテスト・文書更新を一組にする。指摘箇所だけを変えて、同じ経路や既存の制約を壊さないか確認する。
2. 指摘の成立条件を確かめる検証と、利用先の必須チェックを実行する。実行していない検証は成功とせず、修正済みと検証済みを分ける。
3. 修正差分をセルフレビューする。PR への反映を求められた場合は必要なコミット・push まで行う。コミットは [commit-changes](../commit-changes/SKILL.md) に従い、独立した目的で分割する。コメント数に合わせて機械的にコミットを分けない。
4. PR へ反映した場合は head の SHA と差分を確認し、CI の成功・失敗・実行中を区別する。ローカルだけの修正を PR に反映済みと報告しない。

## 返信とスレッドの状態を揃える

- 返信は結論、変更内容または判断理由、確認結果を短く書く。必要なら反映済みコミットや該当コードをリンクし、定型の謝辞や指摘の全文再掲を重ねない。
- 返信で新たな提案や質問をする場合も、内容に合う接頭辞を付ける。修正・検証結果だけを伝える返信には付けない。
- 投稿前に最新の head と会話を確認する。追加の返信や変更がある場合は内容を照合し、古い判断や重複した返信を送らない。
- 行・ファイルへの返信は元のスレッドへ、一般コメントへの返信は対象が分かる引用やリンクを添えて投稿する。送信後は本文と投稿先を確認する。
- タイムアウトなどで送信結果が不明なら、会話を再取得して投稿の有無を確認する。成否を確認できないまま再送しない。
- スレッドを解決するのは、操作が依頼範囲にあり、指摘の解消を確認でき、必要な修正が PR に反映され、未回答の問いや対立が残っていない場合に限る。単に返信した、差分が古くなった、今回の対象外と判断しただけでは解決しない。
- 権限やツールが不足する操作は未実施として残し、返信案と対象リンクを渡す。レビューの承認・却下、再レビュー依頼、マージはコメント対応だけの依頼に含めない。

## 結果を返す

対応したコメントと変更・検証結果を示し、未対応事項には理由と次の確認を添える。
コミット・push・返信・スレッド解決は実施したものだけを報告する。対象外や取得できなかった範囲がある場合も明記する。
