# 実装変更を pulse の監視設計へ渡す

実装前に利用経路・成功や失敗の判定・指標やログ・依存先の変更を調べ、既存の監視と初動への影響を確認する。
影響があれば、利用可能な pulse の `plan-monitoring` を使う。設計時の監視案がある場合は、その案と実際の差分を照合し、変わった範囲だけ見直す。

- 要求・設計・対象SHAまたは識別できる差分、変更前後の挙動、利用者への影響、対象環境を渡す。計画中・実装済み・適用済みを区別する。
- 実在する指標・ログの名前と定義、既存の通知条件・通知先・初動、合意済みの目標を渡す。新しく計測する予定の情報は、取得済みとして示さない。
- 新旧版が共存する場合の観測対象、切替・切り戻しの条件、旧監視を外す条件を渡す。マージやPR作成を、監視の適用や撤去の根拠にしない。

返された監視案の指標・条件・初動と、実装した挙動を照合する。計測・監視設定の実装も依頼範囲に含まれる場合は、必要な変更と検証を進める。範囲外の作業は依存作業と未対応事項として返す。
提出時は対象の版、監視への影響、設計・実装・適用・通知検証の実施状況、残る計測不足と次の対応を添える。実環境への適用・試験通知は、元の依頼と操作範囲に従う。
pulse が未導入でも同じ情報を整理し、実装を進められる範囲と運用開始前に確認する条件を分ける。
運用改善の効果評価は `improve-operations`、変更に合わせた指標・通知・初動の設計は `plan-monitoring` に渡す。
