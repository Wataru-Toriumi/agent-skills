# 分割とメッセージの例

## 分割の判断

| 変更 | 分け方と理由 |
| --- | --- |
| ルートの開発ガイド分離と、独立した三つのプラグインの説明整理 | ガイド分離と各プラグインで四つに分ける。それぞれ別に採用・取り消しできる |
| 同じプラグインで、不具合修正と無関係な命名整理 | 別コミットにする。同じ配布単位でも目的が異なる |
| 不具合修正と、その挙動を確認するテスト | 一つにまとめる。修正と根拠を一緒にレビューできる |
| 文書の移動とリンク更新 | 一つにまとめ、途中でリンク切れにしない |
| API と全呼び出し元の互換性を壊す変更 | 整合する単位にまとめる。互換層などで各段階が成立する場合は段階的に分けられる |
| 同一ルールによるリポジトリ全体の整形 | 一つにまとめられる。整形に機能変更は混ぜない |

バージョン更新などが必要なら、各配布単位の規約に従って関連コミットへ含める。
同じプラグイン内で複数に分ける場合も、コミットごとのバージョン更新を一律に要求しない。
