# sketch と連携して監視・障害・運用改善の説明を整える

内容と根拠が固まったら、推敲・図解や指定形式への変換に、利用可能な `sketch` のスキルを使う。表現が整っていればそのまま返す。

## 表現を選ぶ

| 必要なこと | スキル |
| --- | --- |
| 日本語の重複・構成・言い回しを整える | `polish-writing` |
| 関係・状態・操作順を図で説明する | `draw-mermaid` |
| Marp・Google スライドで発表資料を作成・編集する | `create-slides` |
| HTML の説明ページを作る依頼に応える | `explain-visually` |

指定された書式・出力先を優先する。文章やレビューの依頼だけで、スライド・HTML・別の保存ファイルを増やさない。
Google スライドでは対象 URL・新規作成か既存更新か・テンプレート・保存先も引き継ぐ。資料の作成と共有設定の変更・通知は分け、元の依頼範囲を保つ。
スキルが利用できなくても、元の作業を続け、必要な文章や表で説明する。自動でインストールしない。

## 渡して照合する

1. 読者・理解や判断してほしいこと、対象の本文や資料、変更する範囲、出力形式・保存先を渡す。元資料の参照先と、確定事項・提案・未確認の区別を添える。
2. 影響範囲、時刻・タイムゾーン、観測事実と仮説、操作と結果、指標の定義・期間、対策の担当・期限と合意状況を、今回の説明に必要な範囲で渡す。
3. 整えた本文・図などと、内容上の確認事項・描画や検査の実施状況を受け取る。軽減・復旧・原因解消を混同せず、時系列の前後関係を因果と断定していないか確認する。未合意の担当・期限、推定や目標を確定事項・実測値に変えない。
4. 元のスキルが求める項目と書式を成果物に反映する。矛盾があれば元の要求・差分・記録で確かめる。描画・文章検査の結果と、内容を検証した結果は分けて記す。

投稿・公開・通知などは、元の依頼で認められた範囲のまま扱う。
障害対応中は影響の軽減と状況共有を優先し、推敲や描画の完了を待たせない。
