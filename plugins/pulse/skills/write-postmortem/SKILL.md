# 障害を振り返る

当時の情報と制約から経緯を説明し、再発や影響を減らす行動につなげる。
[Blameless postmortem](https://sre.google/sre-book/postmortem-culture/) の考え方を使い、個人の注意不足で分析を終えない。

## 事実と要因を整理する

1. **影響を確かめる:** 利用者・機能・期間・規模を、記録や計測の根拠と対応させる。影響の開始、検知、軽減、復旧の時刻を区別し、欠けた記録は不明とする。
2. **経緯を再構成する:** 判断に影響した出来事と操作を時系列に並べる。出典とタイムゾーンを残し、記録の矛盾や当時分からなかった情報を示す。
3. **要因を追う:** 発端、影響を拡大した条件、検知・復旧を遅らせた要因を分ける。相関を因果とせず、単一の根本原因や決まった回数の「なぜ」に押し込めない。
4. **対策を選ぶ:** 各要因に、予防・早期検知・影響軽減・復旧短縮の対策を結び付ける。有効だった仕組みも残し、仕組みや手順を変えずに「周知・注意する」だけで閉じない。

原因が未確定でも記録を作り、残る仮説と検証方法を示す。復旧したことを、原因が解消した証拠にしない。

## 短くまとめる

既存の書式を優先し、概要・影響、主要な時系列、寄与要因と根拠、有効だった対応、改善策、未解決事項を必要な範囲で書く。
改善策には優先度の理由・担当・期限・完了条件を付ける。未合意の担当や期限は候補・未定と明示する。
詳細ログは参照に置き、本文に転記しない。

既定の出力先は会話。指定があれば保存する。公開・課題登録は依頼の範囲で行う。
複数の障害や運用負荷を横断して優先度を決める場合は [improve-operations](../improve-operations/SKILL.md) を使う。
