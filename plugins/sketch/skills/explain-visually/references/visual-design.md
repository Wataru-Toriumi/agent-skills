# 表現とデザイン

## 図で何を答えるか

| 読み手の問い | 表現 | 残す情報 |
| --- | --- | --- |
| 何がつながり、どう動くか | 構成図・シーケンス・フロー | 境界、方向、受け渡すもの、条件 |
| 変更で何が変わるか | 同じ配置の変更前・変更後 | 追加・削除・維持する箇所、影響 |
| どの案が条件に合うか | 同じ比較軸の表、必要なら案ごとの小図 | 判断軸、制約、不利な点、未確認 |
| どこが違い、どれほどか | 同じ尺度のグラフ | 単位、期間、母数、出典 |
| 順番や条件で何が起きるか | 図の段階表示・条件切り替え | 現在の条件、遷移理由、結果 |

箱に機能名を並べるだけで終わらず、説明したい経路や変化を示す。
矢印の意味が曖昧なら「保存する」「通知する」などの動作を添える。複数の意味を一つの線種へ押し込まない。
比較では配置・用語・縮尺を揃え、変わる箇所だけを強調する。長い条件の比較は無理に図解せず、表を使う。
一図の説明は読み取る結論と成立条件へ絞り、要素の一覧を文章で再掲しない。

## 視線を整える

- 一番伝えたい図や主張を大きくし、補足との強弱を付ける。すべてを同じカードに収めず、余白と見出しで関係を示す。
- 既存デザインを優先し、指定がなければ中立色を土台に強調色を絞る。色はラベル・形・線種と併用し、[sketchの配色](../../draw-mermaid/references/colors.md) と意味を揃える。
- 本文は読みやすい幅へ収め、図表には必要な幅を渡す。狭い画面では列を積み替え、図だけをスクロールさせる。文字を縮めて全体を押し込まない。
- SVGには `viewBox` を設定し、日本語の折り返しは `tspan` などで意味の区切りを選ぶ。本文・図・スライドへの埋め込み後にも欠けや重なりを確認する。
- 数値を揃えて比較できるよう、表では数値を右寄せし桁幅を揃える。単位と比較基準を明記し、棒の長さや軸の省略で差を誇張しない。

## 動かす理由を明確にする

段階を進めるたびに、図と説明の対応箇所を変える。説明文だけが変わる操作や、理解に関係しない動きを増やさない。
概要へ戻る操作を用意し、状態を色だけで表さない。切り替え前後で同じ要素の位置を保ち、目で追えるようにする。
重要な条件はホバーだけに隠さず、クリック・キーボード・静止表示でも読めるようにする。
