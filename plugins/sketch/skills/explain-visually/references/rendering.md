# 描画と共有

## 単一HTMLとして確かめる

1. HTMLだけを空のディレクトリへコピーし、キャッシュに頼らないブラウザー環境で通信を遮断して開く。ローカルサーバーを起動したまま成功した結果だけで単独動作としない。
2. ネットワーク記録を確認し、表示や操作のための外部通信・別ファイル参照がないことを確かめる。出典リンクの遷移とは区別する。
3. 通常の幅と狭い幅で全体を見て、図の欠け、日本語の折り返し、見出しと図の強弱を確かめる。横スクロールが必要なら図表の領域内に収め、操作できるようにする。
4. 段階の進む・戻る・概要への復帰、比較条件の切り替えを試す。キーボードのフォーカスと選択状態、説明と図の一致、コンソールのエラーも確認する。
5. 動きを減らす設定、JavaScript無効、印刷プレビューで、隠れた段階や条件が失われないか確認する。図の動きを検証したことと、対象システムを実行したことを区別する。

静止したページでは存在しない操作を検査項目に増やさない。環境不足なら繰り返し試行せず、確認できた表示・操作と未確認を分けて伝える。
ブラウザーの画像またはプレビューを実際に見て直し、構文検査だけで見た目も確認済みとしない。

## 内容と操作範囲を照合する

| 依頼例 | 確認する結果 |
| --- | --- |
| READMEのMermaidを読みやすくして | `draw-mermaid`でソースと掲載先を扱い、HTMLへ勝手に置き換えない |
| 二つの設計案をHTMLで比較して | 同じ比較軸で違いと制約を示し、未確認の性能を数値で補わない |
| 処理の流れを順に見たい | 操作と図の段階が対応し、架空の再生を実システムの監視と扱わない |
| 作成済みレビュー結果を説明して | 指摘・根拠・対象コミットを保持し、表示を整えたことで承認済みとしない |

既存ツールでレビューや設計の判断が済んでいれば、その結果を受け取る。説明資料の作成だけでPR投稿・公開・リポジトリの設定変更まで進めない。

## 渡し方

HTMLへのリンクと、ダウンロードしてブラウザーで開く方法を伝える。共有サービス内のプレビューでの動作は前提にしない。
実際に確認したブラウザー・画面幅・操作と未確認事項を短く添える。PDFも求められた場合は静止した別成果物として出力・確認する。
