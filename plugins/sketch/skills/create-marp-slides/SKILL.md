# Marp で伝わるスライドを作る

読み手が理解・判断・行動できる順序に内容を組み立て、実際の表示で読みやすさを確かめる。
指定された内容・ブランド・テンプレートを優先し、見栄えのために根拠や条件を削らない。

## 目的と成果物を決める

- 読み手、伝えたい結論、発表時間または枚数、投影用か配布用か、必要な形式を確認する。資料から分かることは聞き直さず、不足する前提だけを示す。
- 元資料の事実・数値・出典と提案・仮定を区別する。架空の実績やグラフを作らず、情報が足りない箇所は未確認とする。
- 既存デッキでは内容と参照先を保ち、依頼された範囲を改善する。構成案だけの依頼では、不要なテーマや出力ファイルを増やさない。
- ソースは Markdown とテーマ CSS、必要な画像を一組にする。形式の指定がなければ、同じソースから発表用 HTML と配布用 PDF をセットで作る。ソースのみ・特定形式のみの指定は優先する。
- 発表用 HTML は画像・CSS・JavaScript を埋め込み、1ファイルだけでオフライン再生できる形にする。フェード、進捗アイコン、動的SVGと停止操作を保つ。
- 出力に使う Marp とブラウザーを確認する。形式ごとの確認と PPTX の編集可否は [描画と出力](references/rendering.md) に従って扱う。

## スライドごとの主張を組み立てる

1. 全体の結論と、読み手に求める判断や行動を短く示す。各スライドの見出し・主張・根拠・表現を並べ、話のつながりを確認する。構成の確認を求められていなければ、そのまま制作へ進める。
2. 一枚で伝える主張を絞り、見出しを読むだけでも要旨を追えるようにする。最後のまとめスライドはタイトルを「まとめ」とし、結論と次の行動を本文に置く。結論、根拠、比較、手順などに合わせて [構成とデザイン](references/design.md) から表現を選ぶ。
3. 発表者が話せる補足はノートへ、読み手の判断に必要な条件と出典はスライド上へ残す。配布用には口頭説明がなくても理解できる文脈を足す。

## Markdown とテーマを作る

- ブランド指定がなければ、16:9、落ち着いた背景、一つの強調色を起点にする。[テーマ CSS](assets/theme.css) と [デッキひな形](assets/deck-template.md)、ひな形が参照する `assets/images/` を相対配置を保って出力先へコピーする。架空の例を依頼内容へ置き換え、ひな形の枚数や話題に合わせて内容を曲げない。
- front matter、ページ区切り、ページごとの指定、画像の配置は [Marp の記法](references/marp.md) に従う。テーマはデッキ全体で共有し、ページ固有の装飾を増やしすぎない。
- 最初の表紙は `cover` クラスでタイトルと補足を上下中央に配置し、左揃えにする。2枚目以降のタイトルは上部の同じ位置に揃え、本文や図表をその下へ配置する。
- 表紙はタイトルと補足のみとし、2枚目以降の要点は下部の固定メッセージ欄に置く。[Marp の記法](references/marp.md#下部に固定するスライドメッセージ)に沿って指定し、本文や図表との重なりを確認する。
- 最下端にページごとに区切った進捗バーを置き、表紙では非表示、最後の「まとめ」ですべて埋める。[進捗バー](references/marp.md#最下端の進捗バー)に沿って現在位置を示すアイコンや配色を調整し、枚数変更後も位置とページが対応するか確認する。
- HTML での発表には短いフェードを標準とし、動きを不要とする指定を優先する。[描画と出力](references/rendering.md#スライド切り替えのフェード)に沿って、ページ送りと戻りをブラウザーで確認する。
- 図、比較表、短いコードなど、根拠を読み取れる表現を選ぶ。Mermaid が必要なら利用可能な `draw-mermaid` で作り、描画済みの SVG / PNG を埋め込む。コードブロックが Marp で図になることを前提にしない。
- 図の動きを求められたら、[画像と図](references/marp.md#画像と図)に沿って動的SVGと静止SVGを用意する。HTMLで停止操作と動作を確認し、PDFと動きを減らす設定には静止版を使う。
- 文字の縮小で詰め込まず、文章を短くする、詳細を移す、ページを分ける順に調整する。改行位置は [改行と折り返し](references/design.md#改行と折り返し)に従って選ぶ。色だけで意味を伝えず、ラベルも付ける。

## 描画して仕上げる

1. [描画と出力](references/rendering.md) に沿い、指定された形式、指定がなければ HTML と PDF へ変換する。HTML は [単一ファイル化](references/standalone-html.md)まで行う。全ページの画像またはプレビューも用意し、先頭ページだけで済ませない。
2. 全体の一覧で構成と見た目の一貫性を、各ページの実表示で文字の欠け・重なり・余白・図表の読みやすさ・画像や日本語フォントの欠落を確認する。
3. 問題のあるページを直して再描画する。別形式にも納品する場合は、その成果物も確認する。HTML の成功だけで PDF や PPTX も確認済みとはしない。
4. 主張と元資料、出典、ノート、最終の依頼内容を照合する。ページ数や変換コマンドの成功だけで完成としない。

環境不足で描画できない場合はソースを完成させ、未確認の形式と必要な環境を伝える。同じ環境エラーを繰り返さず、確認した参照先以外へローカルファイルのアクセスを広げない。

## 成果物を渡す

Markdown・CSS・画像と、出力ファイルへのリンクを示す。HTML は発表用、PDF は配布用と用途を添える。
閲覧者には HTML だけを共有し、ダウンロードしてブラウザーで開けばよいことを伝える。共有サービス内のプレビューでの動作は前提にしない。
使った Marp のバージョン、確認した形式・ページ、残る未確認事項を短く添える。
編集用ソースは相対配置を保って渡し、変更後は単一ファイル化も含めて再出力することを伝える。
