# 発表資料を作る

## 1. 目的と形式を決める

依頼と元資料から、誰に何を判断してほしいか、発表時間はどれだけか、投影用か配布用かを確認する。構成案だけを求められたら、見出しと要点を指定先に返す。

作成・編集を依頼された場合は、指定された形式を優先する。指定がなければ既存資料と編集・共有する場所から選ぶ。それでも判断できない場合は、どのアプリで編集・発表するかを確認する。

| 依頼・利用場面 | 制作時に読む手順 |
| --- | --- |
| Marp の Markdown を編集する、リポジトリで管理する、オフライン発表用 HTML・配布用 PDF を作る | [Marp での作成と出力](references/marp.md) |
| 手元の動画を PowerPoint で再生し、PPTX ひとつで渡す | [PPTX にローカル動画を埋め込む](references/rendering.md#pptx-にローカル動画を埋め込む) |
| Google スライドで共同編集する、Drive 上のテンプレートから作る、既存の Google スライドを更新する | [Google スライドでの作成と編集](references/google-slides.md) |

挿入する動画に字幕も求められたら、[caption-video](../caption-video/SKILL.md) で作成した字幕付き MP4 を使う。

Google スライドを作成・更新したら、編集用デッキの URL を渡す。配布用 PDF は依頼された場合だけ、保存済みの最終版から書き出す。
Google スライドに手元の録画を載せる場合は、[Drive から動画を挿入する](references/google-slides.md#ローカル動画を挿入する)。

他のプラグインから資料を受け取った場合は、[受け取りと返却の手順](../polish-writing/references/plugin-collaboration.md)に沿って根拠・変更範囲・出力先を引き継ぐ。

## 2. 各ページの主張と根拠を組み立てる

- 見出しを並べ、読み手が結論とその理由を追える順序にする。事実・提案・仮定を区別し、元資料の数値・条件・出典を保つ。
- 指定のテンプレートやブランドに合わせ、既存資料を編集する場合は寸法・参照先・変更対象を確かめる。新規で指定がなければ 16:9 を起点にする。
- 比較には表、推移にはグラフ、順序や依存には図、並列の要点には箇条書きを使う。話者が補足できる内容はノートへ移し、判断に必要な条件はスライドに残す。[構成とデザイン](references/design.md)
- 内容に合うレイアウトを選び、選択した形式の手順で制作する。Mermaid 図が必要なら [draw-mermaid](../draw-mermaid/SKILL.md) で描画し、掲載先でもラベルが読める大きさにする。
- タスクの移動・分岐・合流を順に見せる場合は、発表者が止めたい工程ごとにスライドを作る。動きはページ内で再生し、再生途中でも通常の送りキー1回で次の工程へ進める。[工程を動きで見せる手順](references/flow-animation.md)

## 3. 最終形式で確かめて渡す

1. 納品する形式ごとに全ページを開き、順序と内容を元資料と照合する。日本語の折り返し、文字や図の欠け・重なり、配色、画像の縦横比を確認する。
2. 問題があれば修正し、該当ページを再確認する。テーマや構成を変えた場合は全体を見直す。
3. 成果物のリンクと確認範囲を渡す。接続や描画に必要な環境が足りない場合は、準備できた内容と未確認の範囲を示す。
