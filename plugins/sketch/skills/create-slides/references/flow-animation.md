# 工程を動きで見せる

## 説明を区切る位置を決める

発表者が足を止めて説明したい状態を並べ、一つの状態にスライドを1枚割り当てる。分岐や処理順を一度に読める図なら、静止図で示す。

| 見せたいこと | スライドの区切り方 |
| --- | --- |
| 処理しながら移動 | 同じタスク T1 を「入力検証」「本文生成」「保存」の順に運ぶ。T1 の印は残し、処理名を更新する |
| 並列処理と合流 | A と B に別々の経路を割り当てる。A の待機中も B は進み、合流後も両方の結果が読める配置にする |
| 分岐・再試行 | 判断をひし形にし、矢印に「はい／いいえ」などの条件を書く。失敗した T1 が待機し、同じ処理に戻って完了する経路を追う |

## 動く部分を作る

1. 工程名・経路・分岐ラベルを固定し、同じ図を次のページへ複製する。各ページのタスクの出発点を、前のページの到着点に揃える。
2. そのページで説明する区間だけ、タスクの印を矢印に沿って動かす。タスクの名前・色を保ち、状態欄の文言だけを切り替える。停止中と完了後も印を残す。合流地点では印を少しずらし、重なって片方が消えて見えるのを防ぐ。
3. ページに入ると動き始め、到着したら止まるようにする。送り・戻りは発表モードの標準操作に任せる。専用の「次へ」ボタン、ページ内のクリック待ち、再生終了を待つキー制御は加えない。

## 出力形式に合わせる

- **Marp の HTML** は Markdown のページ区切りで工程を分ける。区間の動きは SVG などで表す。単一 HTML の完成版で、戻ったページや再訪したページの表示も確かめる。[図の埋め込みと静止版](marp.md#画像と図)
- **Google スライド** や **PowerPoint で動かす PPTX** は工程ごとにページを作り、工程名・矢印・判断条件を編集可能な図形にする。タスクの移動には、発表モードで送り操作を妨げない自動再生効果か、その区間だけを一度再生する透過アニメーション画像を使う。画像にした部分は編集用ソースを残す。変換する場合は、納品先で再生を確かめる。
- **PDF・Marp の標準 PPTX・動きを減らす表示** は工程の到着状態を使う。タスク名・位置・状態が各ページに残り、順に読むだけで同じ流れを追えるようにする。[Marp の形式別の出力](rendering.md)

## 発表モードで試す

「T1 が送信に失敗し、待機後に再試行する」例なら、移動の途中で → または Space を1回押す。すぐに次の工程へ進み、← を1回押せば直前の工程へ戻れるかを確かめる。再生完了後と連続送りでも、1入力で1ページだけ進むこと、T1 が消えず、位置と状態がその工程に対応することを確認する。

PowerPoint や Google スライドでは、対象アプリのスライドショーで試す。構造検査や別形式のプレビューだけを行った場合は、確認した形式と実際に試したキーを報告し、対象アプリでの再生は未確認とする。
