# Google スライドを作成・編集する

## 利用できる手段を選ぶ

Google スライドを扱う専用スキルや接続がある場合は、対応する操作と利用条件を確認して使う。
読み取り、作成・複製、ページ編集、画像の挿入、描画・書き出しを区別する。Drive の検索や読み取りができるだけで、編集もできるとは判断しない。
対応する接続がなければ、認証済みの API・CLI や利用可能なブラウザー操作を確認する。認証情報や固定の保存先をスキルに埋め込まない。

| 依頼 | 対象の扱い |
| --- | --- |
| 新しい Google スライドを作る | 指定された保存先へ新規作成する。未指定なら接続先の既定を使い、実際の保存先を伝える |
| このテンプレートで別資料を作る | 原本を読み、複製先へ内容を反映する。原本は編集しない |
| この資料の指定ページを直す | 資料と対象ページを読み、依頼範囲だけを更新する。全体を作り直さない |
| 構成や修正案だけを出す | 会話や指定された出力先に案を返し、Drive 上の資料は変更しない |

作成・複製後の ID と URL は操作結果から記録する。保存場所や公開範囲を推測せず、共有変更は元の依頼に従う。

## 既存の構造を保って更新する

1. プレゼンテーションとページの ID、要素、ノート、テーマ・レイアウト、版情報を読み、変更箇所を対応付ける。ページ番号だけに依存せず、並べ替え後も対象を照合する。
2. テンプレートでは、内容に合う見本ページの複製や既存レイアウトを使う。画像・グラフ・表の各枠を残す・差し替える・削除するのどれかに割り当て、不要な見本を除く前に完成ページと順序を確認する。
3. 既存の文章を更新するときは、見出し・本文・注釈が混在する書式やリンクを保つ。文字数が変わる場合は範囲を再計算し、全体への一括書式指定で階層を消さない。置換は対象ページ・要素へ限定する。
4. API の一括更新を使う場合は、取得した対象 ID と必要な変更フィールドだけを指定する。版の一致を条件にできる場合は利用し、共同編集との競合時は再取得して差分を照合する。
5. 作成や更新の応答が途切れたら、記録した ID と対象の内容を読み戻して実施済みか確認する。結果不明のまま複製・ページ追加・文字挿入を繰り返さない。確認できなければ、状態不明の操作と再開条件を残す。

## 編集可能な要素を作る

見出し・本文・表・単純な図はネイティブの要素で作り、箇条書きには段落のリスト機能を使う。見本の写真・数値・ノートを今回の資料に合わせて差し替える。
Mermaid 図を画像にしたら編集用ソースも残す。図の各要素を Google スライド上で編集したい場合は、図形と線で組み立てる。

## 素材と変換を扱う

画像の挿入方法・対応形式は利用する接続の仕様を確認する。URL が必要でも、挿入のためだけに素材や Drive の共有範囲を広げない。
安全に挿入できる手段がなければ、図形で表せる範囲を作り、未挿入の素材を明記する。

編集可能な PPTX などを経由する場合は、Google スライドへの変換後に本文・図形・表が編集できるかを読み戻して確認する。
元ファイルの描画だけで最終表示を確認済みにしない。Google 側のフォント・改行・ノート・リンクの変化も確認する。
接続や変換が使えない場合は、合意した代替形式または構成案を渡し、Google スライドへの反映は未完了と伝える。

## ローカル動画を挿入する

1. 指定されたファイルを開き、内容・形式・縦横比と、載せるページを確認する。たとえば「`demo.mp4` を3枚目に」の場合は、デッキを読み戻し、現在の3枚目のページ ID を取得する。
2. 指定された保存先の Google Drive に動画ファイルをそのままアップロードし、返されたファイル ID を記録する。同じ動画をすでにアップロードしたと確認できれば、その ID を再利用する。応答が途切れた場合は保存先を確認してから再試行する。動画はスライドから参照されるため、納品後も Drive に残す。
3. 対象ページで「挿入」→「動画」→「Google ドライブ」からそのファイルを選ぶ。API なら `createVideo` の `source` に `DRIVE`、`id` に動画のファイル ID、`elementProperties.pageObjectId` に対象ページの ID を指定する。縦横比を保って配置し、保存後にページと動画の参照元を照合する。[動画の挿入と再生設定](https://support.google.com/docs/answer/97447?hl=ja)・[CreateVideoRequest](https://developers.google.com/workspace/slides/api/reference/rest/v1/presentations/request#CreateVideoRequest)
4. 発表モードで、指定された再生方法・音声・表示範囲を確認する。通常のキー送りを求められた資料では、ページに入ると再生する設定を選び、再生中の →・Space と ← でページを送れるかを試す。Drive の動画処理中や権限不足で再生できなければ、挿入済みかどうかと再生の確認状況を分けて伝える。資料の閲覧者が動画も開けるか確認し、共有範囲を変更するのは依頼された場合に限る。

アップロードや挿入ができない場合は、対象ページと利用できなかった操作を示す。ローカルパスを貼っただけの状態や、静止画だけを配置した状態を動画挿入済みとは扱わない。

## 保存後の確認と納品

保存したデッキを読み戻し、ページ順・本文・表・ノート・リンクと編集性を確認する。全ページの表示を確認し、動画やアニメーションは発表モードでも再生してから、編集用デッキの URL と確認範囲を渡す。共有・公開・通知は依頼範囲に従う。

## 配布用 PDF も依頼された場合

最終デッキから指定範囲を PDF に書き出す。保存した PDF を開き、ページ数・順序・表示を照合する。動画やアニメーションのあるページは、代表フレームや短い説明で操作結果が読み取れるか確認する。必要な修正を反映して再出力し、指定された成果物のリンクを渡す。

API の操作仕様が必要な場合は、公式の [作成と複製](https://developers.google.com/workspace/slides/api/guides/presentations)、[テンプレートへの差し込み](https://developers.google.com/workspace/slides/api/guides/merge)、[一括更新と版の制御](https://developers.google.com/workspace/slides/api/reference/rest/v1/presentations/batchUpdate)、[サムネイル取得](https://developers.google.com/workspace/slides/api/reference/rest/v1/presentations.pages/getThumbnail)を参照する。
