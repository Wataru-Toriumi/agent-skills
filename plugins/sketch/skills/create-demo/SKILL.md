# 変更を操作デモにする

## 見せる場面を選ぶ

依頼と対象の版・差分から、誰が何を確かめたいかを整理する。変更の効果が画面やコマンド出力に表れる場面を一つ選ぶ。エラーからの復帰を見せるなら、失敗、修正、再試行までを実演する。

## 操作して結果を記録する

1. 参加者が再現できるよう、環境・初期状態・サンプル入力を用意する。データを書き換える操作は、再試行できる作業用コピーやデモ環境で行う。
2. 利用者と同じ入口から操作し、各手順の入力と、結果がどこにどう表示されたかを記録する。変更前後を比べるときは条件をそろえる。
3. 期待と違っても、実際の表示を記す。環境や権限の都合で試せない手順には「未実行」と期待結果を記す。

## デモを渡す

開始条件と各操作の見どころをまとめ、参加者が実演を見て答えられる問いを一つ添える。[操作デモの出力例](examples/plugin-check.md)

保存先・形式の指定や「会話だけで」という依頼を優先する。指定がない場合は用途で決める。

- **スプリントレビュー用**の手順は Markdown に保存し、会話で保存先を示す。同じデモの手順があれば更新する。新規ならプロジェクトの慣例に従い、決まりがなければ `docs/demos/<題材>.md` に作る。
- **その他のデモ**は会話で返す。

録画を依頼されたら操作を収録し、再生して入力と結果が読めるか確かめる。字幕には [caption-video](../caption-video/SKILL.md)、発表資料には [create-slides](../create-slides/SKILL.md) を使う。PR への投稿や動画の公開は、依頼された場合に行う。
