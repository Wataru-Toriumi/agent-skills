# 動的表現の選択と検証

## 目的から選ぶ

| 目的 | 方法 | 条件・例 |
| --- | --- | --- |
| 通信などの流れを強調する | flowchart のエッジをアニメーションさせる | [エッジのアニメーション](../examples/edge-animation.md) |
| 決まった順番で経路を見せる | エッジに `step` を指定する | Mermaid 12.3以降。[順番の再生](../examples/step-animation.md) |
| 関連資料を開く | ノードに `click` でリンクを付ける | 掲載先の設定に依存。[ノードのリンク](../examples/node-link.md) |
| クリックに応じて処理する | `click` とホスト側の JavaScript コールバックを組み合わせる | スクリプトを実行・設定できるページが必要 |
| データや操作に合わせて図を変える | ホスト側で図の定義を更新し、`mermaid.render` で再描画する | 更新処理は Mermaid のコードブロックの外に実装する |

エッジの動きは流れを説明する演出であり、実際の通信や処理の実行を示すものではない。
状態遷移のシミュレーションでは、入力・遷移条件・現在の状態を管理する処理を別途用意する。
既存のアプリへの組み込みや HTML の作成は依頼範囲に合わせ、作図だけの依頼からアプリ全体の実装へ広げない。

## 掲載先と静止版

- 利用先の Mermaid バージョン、SVG の埋め込み方、スクリプトや設定の制限を確認する。ローカルの HTML で動いても、Markdown の掲載先で同じように動くとは限らない。
- JavaScript コールバックは `securityLevel: strict` では無効になる。URL リンクの扱いも掲載先で確認し、図の外に通常のリンクを添える。対応のために設定を無断で `loose` へ変更しない。
- 動きを減らす設定や印刷・PNG 出力でも、方向・順番・条件をラベルや番号から読み取れるようにする。古いレンダラー向けには未対応の指定を除いた基本構文の静止版を用意する。
- 動かす線は説明に必要なものに絞る。独自ページで継続的な動きを使う場合は、停止操作や動きを減らす設定を扱えるようにする。

## 再描画を組み込む場合

`mermaid.render` が返す SVG を表示先へ反映する。イベントの設定が必要なら、挿入後に返された `bindFunctions` を呼び出す。
使い方は [Mermaid の描画 API](https://mermaid.js.org/config/usage#api-usage) を参照する。

- 更新に使うデータとタイミングを決め、状態や表示値の根拠を保つ。未確認の状態を成功や完了として表示しない。
- 再描画は順番に処理するか、古い結果が新しい表示を上書きしないようにする。描画失敗時は最後の正常な図を保ち、更新失敗を示す。
- 自動レイアウトによる位置の変化も確認する。連続した移動や滑らかな遷移が必要なら、再描画だけで実現できると約束せず、別の表示処理を検討する。

## 動作を確認する

1. 対応バージョンのブラウザープレビューで、意図した線・順番だけが動くか確認する。SVG を差し替えた場合は再生が始まるかも確認し、必要なら SVG の再生時刻を初期化する。動きを止めた状態でも意味が残るかを見る。
2. リンクは遷移先を確認する。コールバックや再描画は操作後の変化、連続操作、再描画後のイベント、失敗時の表示を確かめる。副作用のある操作は検証用のデータや処理で試す。
3. 静止版も描画し、ラベルと経路が動的版と一致するか確認する。
4. 構文、見た目、動作、掲載先での確認を分けて報告する。SVG の生成成功や PNG の確認だけで動作確認済みとしない。
