# C4 の使い分け

読者が知りたい範囲を選ぶ。すべてのレベルを作る必要はない。

| 問い | 図 | 残す情報 |
| --- | --- | --- |
| 誰が使い、どのシステムと関わるか | [Context](../examples/c4-context.md) | 人、対象システム、外部システム、関係の目的 |
| 内部をどのアプリとデータストアで構成するか | [Container](../examples/c4-container.md) | システム境界、責務、技術、接続 |
| 一つのアプリ内部の責務をどう分けるか | Component | 対象Container内のコンポーネントと依存 |
| 実行時にどの順で連携するか | Dynamic、または sequenceDiagram | 特定シナリオの呼び出しと応答 |
| どの環境に何を配置するか | Deployment | 配置先、インスタンス、環境ごとの構成 |

Context と Container で同じ要素の名前を揃え、どのシステムを展開したか明示する。異なる粒度を同じ箱として並べない。
コード内部まで必要なら別図に分ける。利用者の目的はユースケース図、体験と困りごとは journey で扱う。

## Mermaid で描く際の注意

- 掲載先が専用構文に未対応なら、境界と粒度を保った flowchart、または対応環境で描画した SVG を使う。
- C4 は要素の宣言順と `UpdateLayoutConfig` で配置を調整する。PlantUML のレイアウト指定をそのまま移さず、ラベルの位置と線の交差を描画して確認する。
- 配色は C4 用の `UpdateElementStyle` などで調整する。例は明るい背景向けの固定色であり、暗い背景では文字・塗り・枠も調整する。
