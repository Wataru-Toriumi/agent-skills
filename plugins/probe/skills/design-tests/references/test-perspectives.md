# 対象別のテスト観点

変更が影響する対象を選び、要求や差分から「どの条件で、何が起きれば失敗か」を具体化する。複数の対象にまたがる変更では、受け渡したデータと最終状態を、合意した契約や反映期限と照合する。対象に共通する品質は[テストの分類と選び方](../../plan-tests/references/test-types.md)を参照する。

## ネイティブアプリ

| 観点 | 条件と確認する結果 |
| --- | --- |
| 中断と復帰 | 入力中や送信中にバックグラウンドへ移し、復帰・再起動時の入力値、送信状態、遷移先を確かめる。 |
| 通知・ディープリンク | ログアウト中にリンクを開き、認証後の遷移先を確かめる。別アカウントで開いた場合は表示されるデータの範囲も見る。 |
| 端末権限 | OS の権限を拒否・取り消した状態で対象機能を開き、案内と、その状態で続けられる操作を確認する。 |
| 通信と端末内データ | オフラインでの操作や通信復帰後の同期で、未送信データの表示とサーバーの保存結果を照合する。 |
| 端末・版の違い | 対応する OS、画面サイズ、文字サイズで主要操作を試す。アプリ更新時は旧版で保存したデータを読み出せるか確かめる。 |

## Web フロントエンド

| 観点 | 条件と確認する結果 |
| --- | --- |
| ナビゲーション | URL の直接入力、再読み込み、戻る・進むで、表示内容と URL、入力状態が仕様どおりに対応するかを見る。 |
| キャッシュと複数タブ | 一方のタブでログアウトし、もう一方で履歴に戻る。キャッシュから再表示される内容と、更新操作の結果を確かめる。 |
| 非同期表示 | 読み込み中、結果が空、通信失敗を区別できるか確かめる。連続検索では応答順が逆でも最後に選んだ条件と表示が一致するかを見る。 |
| フォーム操作 | 入力エラー後の値とフォーカス、連打時の送信回数、完了表示を確認する。 |
| 表示とアクセシビリティ | 対応ブラウザー、画面幅、拡大表示で主要操作を試す。キーボードや読み上げで入力・エラー確認・修正まで進めるかを見る。 |

## バックエンド

| 観点 | 条件と確認する結果 |
| --- | --- |
| API 契約と認可 | 正常な入力、境界値、権限の異なる利用者で応答と保存結果を照合する。拒否時は更新や通知の有無も確認する。 |
| 同時更新と再送 | 同じ対象への更新が競合した場合や応答消失後に再送した場合に、採用された値・記録件数・副作用を確かめる。 |
| 依存先の障害 | 保存や外部サービスの呼び出しが途中で失敗したとき、呼び出し元への応答、確定済みの処理、再試行の開始状態を確認する。 |
| データ移行と新旧版の共存 | 段階リリース中の書き込み順を再現する。旧版が保存した値を新版が読めるか、新版が追加した値を旧版の更新で失わないかを確認する。 |
| 互換性と負荷 | 契約変更では対応する旧クライアントや保存済みデータを使う。処理量が変わる場合は合意した件数・同時数で応答時間やエラー率を測る。 |

## バッチ処理

| 観点 | 条件と確認する結果 |
| --- | --- |
| 処理対象と時刻境界 | 対象が 0 件の場合と、締め時刻の直前・一致・直後のデータで、業務上のタイムゾーンに沿った対象件数と出力を照合する。 |
| 中断と再実行 | 一部を保存した後で処理を中断し、同じ対象期間で再実行する。再開位置と最終出力から欠落・二重計上を調べる。 |
| 遅着データと再集計 | 締め後に過去日付の訂正が届いた場合に、再集計の対象期間と訂正前後の合計を照合する。同じ訂正を再処理しても二重計上しないかを見る。 |
| 起動の重複 | 定期実行と手動実行が重なったとき、後続の起動がどう扱われるかを実行履歴と出力で確かめる。 |
| 完了と異常の検知 | 想定件数を期限までに処理できるかを測る。一部失敗時は処理件数・失敗件数・終了状態から、運用者が再処理の対象を特定できるかを見る。 |

## 非同期処理・システム間連携

| 観点 | 条件と確認する結果 |
| --- | --- |
| 重複配信 | 同じ予約イベントが再配信されたとき、予約 ID を手掛かりに送信元の記録と受信側の通知件数を照合する。 |
| 順序逆転と遅延 | 更新イベントが古い順に届かない場合に、受信側の最終状態を確かめる。反映期限が決まっていれば経過時間も測る。 |
| 部分失敗と復旧 | 受信側で保存した直後、処理完了を通知する前に停止した場合を扱う。再開後の未処理件数、保存件数、外部への送信件数を照合する。 |
