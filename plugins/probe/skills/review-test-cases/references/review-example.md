# レビュー例

## 入力

架空の予約変更 API に、本人だけが人数を変更できる制限を追加する。
要求は「本人は1〜6人に変更でき、範囲外の人数や他人の要求は拒否され人数も変わらない」。
API への直接アクセスは可能。方針には「画面の正常系だけを確認」とある。

| ケース | 内容 |
| --- | --- |
| T1 | 本人が3人から4人へ変更し、「正常に動く」ことを確認 |
| T2 | 他人には画面のボタンがないため、変更要求は成立しないとして除外 |

## 指摘

| 区分・対象 | 指摘と最小限の修正案 |
| --- | --- |
| 方針の不足・T2の誤った除外 | ボタンがなくても API に要求は届く。実施前に認可の検証を方針へ加え、T2を他人の要求の拒否と保存人数の維持を確かめるケースにする |
| ケースの問題：T1 | 「正常」では保存失敗を判定できない。成功応答と、再取得した人数が4人であることを期待結果にする |
| ケースの問題：人数の境界 | T1だけでは範囲の誤りを見逃す。0・1・6・7人のケースを補う |

同時更新の勝敗は要求から決まらないため、欠陥と断定せず確認事項にする。
これは机上レビューの例であり、実行結果ではない。
