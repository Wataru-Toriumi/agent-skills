# 抽象解釈と有界モデル検査

## 抽象解釈: Astrée、Frama-C Eva

1. 解析対象の言語、入口、ビルド条件、整数・浮動小数点の意味、環境モデルを定める。外部関数・割り込み・入力を都合のよい値に固定しない。
2. 調べる実行時エラーや値域を選び、対象コードが解析へ到達しているか確認する。対応しない構文、欠けた関数本体、仮定した振る舞いを記録する。
3. 警告を対象へ照合する。過大近似による警告は具体的な実行で再現するとは限らない。精度を上げる場合は分割・注釈・モデルの根拠を示す。
4. 警告なしの意味は、解析した性質・コード・環境とツールの保証に限定する。未解析や解析失敗、無視した警告を成功としない。

Eva では解析処理のエラー・警告と、実行時エラーの可能性を示すアラームを別に確認する。解析処理が成功し、到達した論理条件が証明済みでも、アラームが残る場合がある。

Frama-C の抽象解釈は Eva を選ぶ。別のプラグインである WP の演繹的検証と混同しない。
商用ツールでは利用可能なライセンスと解析対象の対応範囲も確認する。

公式資料: [Astrée](https://www.absint.com/astree/index.htm)、[Frama-C Eva](https://www.frama-c.com/fc-plugins/eva.html)。

## 有界モデル検査: CBMC

1. 対象関数、非決定的な入力、事前条件、assertion を持つハーネスを作る。入力制約で違反経路を除外していないか確認する。
2. 対象アーキテクチャ、外部関数のモデル、ポインター・配列境界・算術など検査する性質を明示する。既定値を推測せず、使用版のオプションを確認する。
3. ループ・再帰の展開範囲と、展開が十分かを調べる unwinding assertion を設定する。展開不足による失敗と、要求した性質の違反を分ける。
4. 反例は入力と実行経路を元のコードで確認する。結果が成功でも、展開の十分性や環境の網羅性が未確認なら、調べた範囲の結果として返す。

実行例は使用版の [CBMC チュートリアル](https://diffblue.github.io/cbmc/cprover-manual/md_cbmc-tutorial.html) を参照する。
