# 状態と関係のモデル検査

## 状態遷移: TLA+ / TLC、SPIN、Quint

1. 状態変数・初期状態・操作・障害を要求に対応付ける。読み取りと更新の間に競合できるなら、その区間を一つの操作へ潰さない。
2. 不変条件、デッドロックの扱い、最終的な進行の条件を個別に定める。正常な終了状態と意図しない停止を区別し、進行にはスケジューリングや復旧の仮定も置く。
3. プロセス数・キュー長・値域・探索深さを決める。公平性や状態制約で、検出したい失敗を除外していないか確認する。
4. 使用版の公式手順でモデルを検査する。シミュレーション、ランダム探索、有界探索、到達状態の全探索を区別し、選んだバックエンドと終了状態を記録する。
5. 反例の操作列を元の設計へ戻す。探索を完了しても、そのモデルと範囲を超える入力や実装の保証には広げない。

Quint の実行方式や SPIN の探索設定によって、網羅性と資源消費が異なる。サンプリングや近似的な探索を全探索と報告しない。

公式資料: [TLC](https://docs.tlapl.us/using:tlc:start)、[SPIN](https://spinroot.com/spin/Man/Manual.html)、[Quint のモデル検査](https://quint.sh/docs/model-checkers)。

## 関係: Alloy

1. 対象を集合・関係で表し、型、多重度、所有や参照の制約を定義する。検証したい結論を前提の facts に入れない。
2. `run` で前提を満たすインスタンスを調べる。空の集合だけで成立していないか、実際に検証したい構成が含まれるか確認する。
3. 性質を assertion にし、`check` で反例を探す。要素数、exact 指定、整数ビット幅、時間を扱う場合のステップ範囲とバックエンドを記録する。
4. 反例なしの場合は、選んだコマンド・スコープでの結果として返す。有限スコープの結果を任意サイズでの証明と呼ばない。

公式資料: [Alloy の概要](https://alloytools.org/about.html)、[run / check とスコープ](https://alloytools.org/spec.html)。
