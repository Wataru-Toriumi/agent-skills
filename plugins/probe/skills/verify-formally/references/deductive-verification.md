# プログラム検証と定理証明

## 契約による検証: Dafny、Why3

1. 入力型、事前・事後条件、変更してよい状態を仕様から定める。契約を満たす入力が存在するか、呼び出し側が事前条件を満たすかも確認する。
2. ループ不変条件や補題を補い、必要なら減少する量で終了性を示す。終了性を除外した検証と、終了まで含む検証を区別する。
3. 対象の版で検証義務を生成・実行し、未証明の義務、タイムアウト、信頼した外部関数や仮定を記録する。証明できないことだけでは、不具合の存在は確定しない。
4. 検証を通すために事前条件を強めたり事後条件を弱めたりしない。仕様変更を試す場合は元の結果と分ける。

別言語のコードを Dafny / WhyML に書き直した場合、検証対象はその記述。元のコードとの算術・状態・例外の対応を確認するまで、元の実装を証明済みとしない。

公式資料: [Dafny の契約・不変条件・終了性](https://dafny.org/latest/OnlineTutorial/guide)、[Why3](https://why3.org/)。

## 定理証明: Lean、Coq / Rocq、Isabelle

1. 命題、量化する対象、仮定を定義する。検証対象の主張を公理として追加して済ませない。
2. 既存の定義・補題を使い、証明支援系で証明を検査する。使用したライブラリと版を固定して再現する。
3. `sorry`、`Admitted`、`admit`、`oops` など、未証明・放棄の扱いを使用ツールで確認する。終了コードだけで完成とせず、対象定理とその依存先に残る穴・公理を調べる。
4. 公理が使われていること自体と、未証明の目標を仮定したことを区別する。採用した論理・公理の下で何を証明したかを報告する。

形式化した命題と元の要求の対応もレビューする。数学的な証明が完成しても、接続していない製品コードの正しさまで保証しない。

公式資料: [Lean の公理と計算](https://lean-lang.org/theorem_proving_in_lean4/Axioms-and-Computation/)、[Rocq の証明コマンド](https://rocq-prover.org/doc/V9.0.0/refman/proof-engine/vernacular-commands.html)、[Isabelle](https://isabelle.in.tum.de/overview.html)。
