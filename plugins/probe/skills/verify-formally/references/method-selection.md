# 手法の選び方

ツール名から始めず、確かめたい命題と、モデル・コードのどちらを検証するかで選ぶ。
既存の仕様言語、ツール、担当者の経験があれば優先する。複数の手法を全件に適用しない。

| 対象・問い | 手法と代表ツール | 選定時に確認すること |
| --- | --- | --- |
| 操作順序・再送・競合で不変条件や進行条件が崩れないか | モデル検査: TLA+ / TLC、SPIN、Quint | 原子性、通信・障害モデル、公平性、状態空間。シミュレーションと網羅的な探索を区別する |
| 所有・所属・参照などの関係が制約を満たすか | 関係モデル検査: Alloy | 要素数、整数ビット幅、時間範囲。対象を DB に限定せず、構造や権限関係にも使う |
| 関数やアルゴリズムが契約を満たし終了するか | 自動プログラム検証: Dafny、Why3 | 事前・事後条件、ループ不変条件、終了性、フレーム条件、対象コードとの対応 |
| 帰納的な構造や一般の入力について命題を証明したいか | 定理証明: Lean、Coq / Rocq、Isabelle | 形式化・補題・ライブラリの維持負担、公理、未証明の穴、実装との接続 |
| 制約が両立するか、性質に違反する割り当てがあるか | SMT/SAT: Z3、cvc5 など | 理論・型・量化、符号やビット幅、問い合わせる式と sat / unsat の意味 |
| 到達する値の範囲や実行時エラーの可能性を静的に調べたいか | 抽象解釈: Astrée、Frama-C Eva | 対応言語、入口・環境モデル、解析範囲、過大近似による警告、精度と費用 |
| コードの実行経路を一定の展開範囲で検査したいか | 有界モデル検査: CBMC | ハーネス、入力制約、ループ・再帰の展開、メモリモデル、検査する性質 |

これは目的から選ぶための分類。SMT は他の検証器の内部でも使われ、Frama-C もプラグインによって手法が異なる。
導入の難しさはツールの設置だけでなく、対象のモデル化、補題や注釈の追加、結果の解釈、変更時の追従で見積もる。

## 選定例

- 同時予約で一つの枠を二者が確保する疑い: 読み取りと確保を分けた状態モデルで、競合による違反を探索する。
- 所有者と共有先の組み合わせで閲覧権限が漏れる疑い: 関係と許可条件をモデルにし、Alloy または SMT で違反する構成を探す。
- 丸め関数が仕様の上下限を満たすか: 言語と算術の意味に合わせ、契約による検証や SMT を選ぶ。通常の境界値テストで十分な依頼なら範囲を広げない。
- C の配列アクセスを調べる: 特定経路と反例を絞るなら CBMC、広いコード範囲の値域・警告を調べるなら抽象解釈を検討する。

検証する性質が決まらないままツールを導入せず、不明な要求と候補の手法を返す。
